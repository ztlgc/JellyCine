# Android 手机端 UI 布局审查（2026-10-30）

本次审查对象是当前工作区的 Android 手机端，包含尚未提交的界面改动。基准提交为 `db29be6a038cca9b6e4358c8c58957408e0945c1`；结论不代表该提交单独的状态。

采用只读源码审查：从 Activity、AppNavigation、DashboardContainer 追踪实际页面及共享组件，没有修改产品源码，没有构建、安装或启动应用，也未用仓库历史截图冒充当前界面。本报告中的尺寸是 Compose 约束分析；实际裁切外观、字体阈值与导航栏表现仍需原生预览或设备核验。

## 设计语言与依据

- 审查范围：Android `phone/` 当前可达页面及其使用的 `shared/` UI。
- 设计来源：`AGENTS.md`、当前 Compose 实现、`docs/PLAYBACK_REDESIGN_V2.md`。后者只约束普通 Video 详情及通用播放器，不能套用于所有页面。
- 已记录的决定：普通 Video 封面完整显示、标题最多两行、文件名与路径可换行；播放器窄竖屏工具栏可横滑，声音抽屉短屏可纵向滚动。保留这些明确决定。
- 当前实现的视觉语言：深色背景、海报/宽幅图片、圆角卡片和胶囊控件；主界面悬浮底部导航；设置页采用 Material 3 顶栏与分组列表。
- 布局拥有者：`Layout.kt` 负责主界面底部留白和详情宽度；`CompactTopChrome.kt` 负责收起标题；`PhoneDialog.kt` 与 `AmoledUi.kt` 负责通用弹窗；播放器使用 `ControlsOverlay.kt`。
- 明确例外：未见另外记录的例外。没有发现全应用统一字号和间距的强制文档，不能把不同页面的所有数值差异都当作缺陷。

## 各页面检查结果和具体建议

### 首页、搜索、收藏与媒体列表

**首页和收藏：先修文字区高度。** `Dashboard.kt:3002` 将竖海报卡片固定为 214dp，其中图片 166dp，`3084` 的文字区固定 46dp；标题和副标题行高分别为 15sp、13sp，另有 4dp 顶边距和 2dp 行间距。默认字体需要约 34dp，放大到 1.5 倍就约 48dp，超过文字区。建议让文字区自然增高，图片保持现有尺寸，同时去掉卡片固定总高度。收藏页通过 `Favorites.kt:389` 使用同一卡片，一次修改可同时覆盖。

**首页服务器名称应给头像留出确定宽度。** `Dashboard.kt:2120–2173` 的服务器胶囊先作为无权重子项测量，名称没有行数上限；长服务器名可占满整行，后面的头像没有稳定空间。建议头像保留 34dp，明确设置两者间距，服务器胶囊使用剩余宽度，名称单行省略。它影响首页默认分类、其他视频分类和离线页顶部。

**媒体库工具栏应拆分宽度预算。** `LibraryBrowserScreen.kt:167–189` 同行放数量、排序、方向、随机播放、视图和筛选。非随机排序时，四个 IconButton 默认占约 192dp；320dp 窗口扣左右 16dp 后，数量和排序合计只剩约 112dp，再按 0.8:1.4 分配，排序仅约 71dp，内部还要容纳图标及间距。建议将随机播放移入更多操作，让数量与当前排序优先获得空间；筛选与视图保留直接入口。此处已用单行省略防止溢出，但省略不等于信息完整。

**“查看全部”收起页头应使用同一行布局。** `ViewAllScreen.kt:555–580` 将左标题和右计数独立贴边；`CompactTopChrome.kt:265` 左标题上限 148dp，右计数无独立最大宽度。长标题和“已显示 100 / 10000 项”在窄屏或大字体下可能相交。建议返回、标题和计数放入同一 Row，标题占剩余空间，计数使用紧凑格式，避免独立 overlay 互相覆盖。

**搜索：未发现足够强的当前布局缺陷。** 搜索栏测量后把实际高度传给下方内容；输入键盘有 `imePadding`，主导航在键盘出现时隐藏，结果列表使用相应底部留白。后续视觉验收重点是 320dp 横向海报、长片名与大字体，以及未输入时的沉浸推荐在短横屏/键盘状态下的空间分配。不能仅凭使用固定海报宽度判定页面越界。

### 影片、剧集、单集、普通视频、季与人物详情

**紧凑横屏的播放操作区过窄，是最优先修改项。** `Layout.kt:39–57` 把宽度至少 600dp 的手机横屏也纳入详情平板布局，动作宽度返回 0.40；`DetailActions.kt:62–146` 在其中放两个等分文字按钮、预告、收藏及间距。以 600×360dp 为例：内容宽度 540dp，动作行 216dp，扣两枚 40dp 图标与三段 12dp 间距，播放/下载各剩 50dp；播放按钮自身所需的左右 padding、图标、间距已经约 56dp。建议紧凑横屏动作行使用内容全宽。

整剧下载同源：`DetailActions.kt:172` 的 SeriesActionSection 使用同样的宽度比例，640dp 横屏中，扣预告、收藏与间距后，下载约剩 128dp，还需容纳图标和内边距。建议同步取消该行在紧凑横屏的 40% 宽度限制，避免“下载整部剧集”换行后又受到固定按钮高度约束。

**横屏轨道三列需要共同分配宽度。** `TrackSection.kt:75–133` 的视频、音频、字幕各设置最大 230dp，却没有等分剩余宽度；多选内容内部 `279–300` 又使用 `fillMaxWidth`。在内容宽 540dp 的窗口，前两项可各占 230dp，加两段 14dp 间距后，字幕只剩约 52dp。建议 Row 内等分空间，并在字段无法达到可读宽度时切为纵向布局。

**文字回退标题应与图片 Logo 分开决定高度。** `DetailContent.kt:881–915` 用同一个固定高 Box 承载图片和 26sp、30sp 行高的两行标题；高度来自 `DetailScreen.kt:964` 的 74/78dp。两行标题在 1.5 倍字体时约需 90dp。建议图片保持固定高度，文字回退采用自然高度或最小高度。演员姓名 `BoxSetSection.kt:321–331` 的两行 12sp 行高放进固定 24dp，季页 `SeasonDetailScreen.kt:305` 的回退标题同样应检查并去除文字固定高度。

**窄竖屏元信息应有换行退路。** `DetailContent.kt:936` 的评分、年份、完整时长、分级、可选求片入口顺序排列；仅宽屏分支启用横向滚动。元数据齐全且字体增大时，后面的内容获得的宽度会很少。建议窄屏改为 FlowRow，将各段信息视为完整项目；求片入口应保证独立宽度。

**人物页底部应计入导航栏。** `PersonScreen.kt:205–209` 的全屏列表只预留 32dp，父 Activity 与 NavHost 没有为该页消费底部 inset。导航栏高于 32dp 时，列表滚动到底仍可能有末项内容处于系统栏区域。建议底部留白使用 `32.dp + navigationBars inset`。这不是所有详情页的共同结论，普通视频页已经有底部 inset 保护。

**普通 Video 详情及其更多菜单未发现优先级更高的布局矛盾。** 当前路径已使用可滚动列表、底部保护、可换行徽章和受剩余高度约束的更多菜单。标题最多两行及封面完整显示属于已确认设计，不建议在这次审查中随意改成其他模式。

### 播放器与投屏

**跳过片头/片尾提示与控制栏争用底部区域。** `PlayerScreenSections.kt:548–595` 在 ControlsOverlay 之后绘制 BottomEnd 提示，固定底部间距 28dp；`ControlsOverlay.kt:209–247` 的底部 Column 包含进度与工具栏。隐藏系统栏的常见播放状态下，两者在右下区域相交。建议将片头/片尾操作行纳入控制层的底部 Column，安排在进度行上方；控制栏隐藏时再使用独立提示布局，保证两种状态均可见。

**投屏设备弹层应先保证错误提示的高度。** `CastDevicePickerSheet.kt:180–202` 先测量无权重 LazyColumn，最后才测量错误文字。设备多或横屏较短时，列表可能耗尽剩余空间，后面的错误提示无高度可用，列表滚动也找不到它。建议给设备列表 `weight(1f, fill=false)`，让错误文字先获得所需高度。

**长音轨和字幕名需要不同的宽度处理。** 播放器 `TrackSelectionDialogs.kt:467–485` 将名称和说明都限制一行，前缀相同、尾部不同的轨道可能看起来一样。建议完整轨道名允许换行。投屏 `CastingDisplayScreen.kt:459–479` 的横向列表则相反：芯片没有宽度上限，Ellipsis 在无界宽度下不会生效，单个名称可跨越数屏。建议按可用视口限制单个芯片最大宽度，让已有省略逻辑生效，并在详情处提供完整名称。

播放器主控件已有安全区；声音抽屉已有纵向滚动。没有依据把它们报告为“全部缺少安全区”或“横屏面板一律不可滚动”。ExoPlayer 与 MPV 使用同一 Compose 控制层，上述控制层问题需要两个引擎都验收。

### 认证、设置、下载、统计与管理

**认证按钮高度应允许随文字增长。** `AuthScreen.kt:660`、`798–848` 的连接、登录、快速连接按钮固定 50dp。大字体与较长连接码文案需要多行时，内部高度受限。建议改为 `heightIn(min=50.dp)`；连接码作为独立可伸高文字展示，按钮保留动作名。页面已有输入法留白和滚动，不应误报成整个表单没有键盘适配。

**主题曲三分段选择器应允许增高。** `ThemeMusicSettingsItem.kt:64–85` 固定 40dp 并裁切，三个选项等分宽度。320dp 下每段约 85dp，放大后的四字中文可能换行，40dp 无法容纳。建议用内容高度和最小高度；窄屏大字体时采用纵向单选布局。

**通用选择弹窗应为“默认”徽标留宽。** `SelectionDialog.kt:104–125` 内部普通 Row 先测量无限制标签，再测量徽标。大字体的 ExoPlayer、MediaCodec 等名称可占用全部余宽。建议内部标签使用 `weight(1f)` 并允许换行，徽标按自身内容测量。外层已对勾选标记留空间，问题不是整个选项行缺少权重。

**下载列表图片应随行宽收缩。** `DownloadsScreen.kt:1078` 的电影图宽 148dp，`1109–1135` 再放 10dp 间距、文字和操作按钮。320dp 窗口扣页面边距与约 48dp 操作区，文字约剩 82dp；状态又在 `1262` 使用 9sp、单行省略。建议窄屏缩小缩略图，把文字、状态和操作的宽度作为优先预算，状态使用正常 label 字号并允许换行。纵向可滚动不能解决行内信息被省略。

**年度统计标签需避免碰撞。** `ScreenTimeCharts.kt:108–165` 对最多 12 根柱逐根绘制完整时长，文字围绕柱中心定位，没有按文字宽度避让。320dp 页面扣列表和卡片边距后图表约 256dp，每月中心间距约 22dp；相邻月份接近等高且时长为“100h 30m”等时，标签会相互覆盖。页面已有柱点击选择，建议年度只显示选中柱完整时长，其余柱不重复绘制完整值；上下标签区按测量高度预留。这里是文字布局建议，不涉及改变观看数据统计口径。

设置主页、播放器设置、字幕设置、缓存、关于、观看同步、服务器信息的主要内容已使用 Scaffold inset 和滚动列表；本轮没有确认它们存在整页内容不可触达的问题。服务器选择、用户选择、移除确认与同步账号弹窗已有通用安全区/滚动保护。ServerLandingScreen 的极简入口和启动页留白没有充分依据认定为缺陷。

## 最先改什么

首选修复 **紧凑横屏详情操作区的 40% 宽度限制**。这是无需主观视觉判断就能确定的尺寸矛盾，直接影响播放、续播及整剧下载；600/640dp 手机横屏就能触发，修改点也集中。

随后处理播放器底部提示与工具栏重叠，再清理首页/详情/认证/设置中承载文字的固定高度。保持现有深色、海报和圆角视觉语言，不建议为解决这些约束问题进行全应用换肤。

建议原生验收组合：320/360/412dp 竖屏，600×360 与 640×320dp 横屏；字体 100%、150%、200%；长中文名称、无 Logo、多视频版本/音轨/字幕、长路径、相邻月份相同时长；手势和三键导航；播放控件可见时同时出现片头/片尾提示。该矩阵尚未执行。
