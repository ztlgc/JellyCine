# Android 手机端媒体库浏览

媒体库入口统一进入 `phone/.../media/LibraryBrowserScreen.kt`。电影、剧集、其它家庭媒体及混合媒体库使用同一分类栏、工具栏和排序面板。

- 分类：全部、继续播放、合集、类型、标签、收藏、文件夹。
- 工具栏：当前范围项数、随机播放、网格/列表、筛选、排序和方向。
- 排序：创建日期、公众评分、标题、首映日期、官方分级、出品年份、影评人评分、播放日期、比特率、分辨率、文件名、播放时长、随机。
- 分类、排序、方向、布局按服务器会话（含用户）和媒体库保存；筛选留在当前页面会话。
- 类型/标签分组中的标题排序和随机排序作用于分组名称；其它排序字段在分组上没有元数据，使用名称稳定排列。进入分组后使用完整媒体排序。

## 数据和导航

先按 200 项分页读取当前媒体库的完整元数据，再在本地分组、筛选和排序，界面分批显示 60 项。这样文件名、分辨率和随机排序覆盖整个范围，不会在追加分页时变换顺序。缺失排序字段始终放在末尾；同值按名称和 ID 稳定排列。大型媒体库首次加载时间和内存用量会随条目数增长；加载期间显示元数据读取进度。

额外请求字段采用有效的 [Jellyfin ItemFields](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Model/Querying/ItemFields.cs)，常规评分、年份和时长从标准 DTO 读取。无法取得的文件路径、视频流或尺寸不伪造数据。

合集按当前用户可见的 BoxSet 读取成员，并与当前媒体库 ID 集合取交集，避免混入其它库的内容。首次切换合集时读取并缓存成员；刷新媒体库时失效。

文件夹按 `recursive=false` 查询当前层，维护可返回的目录栈。筛选时保留通往匹配媒体的目录。照片复用 Android shared 的图片查看器，支持翻页和缩放。页面退出与目录返回分别处理。

随机播放与随机排序独立：当前筛选范围内可播放媒体组成打乱的队列，剧集展开为当前库内对应集数；播放结束继续下一项，也支持播放器上一项/下一项。照片与文件夹不加入播放队列。队列和当前位置随导航状态保存。

## 验证

```powershell
.\gradlew.bat :phone:testDebugUnitTest :data:testAndroidHostTest -PandroidAbis=arm64-v8a --console=plain
```

媒体库测试覆盖缺失字段位置、Windows/Unix 文件名、视频分辨率、日期时区、稳定随机顺序、剧集队列范围、媒体类型过滤、同值排序、目录筛选、合集筛选。

编译和单元测试与设备安装、界面验收、真实服务器验收分开。本次不包含 TV 或 iOS 的开发和验证。
