# Android 手机端媒体库浏览

媒体库入口统一进入 `phone/.../media/LibraryBrowserScreen.kt`。电影、剧集、其它家庭媒体及混合媒体库使用同一分类栏、工具栏和排序面板。

- 分类：全部、继续播放、合集、标签、收藏、文件夹。
- 工具栏：当前范围项数、随机播放、网格/列表、筛选、排序和方向。
- 排序：创建日期、公众评分、标题、首映日期、官方分级、出品年份、影评人评分、播放日期、比特率、分辨率、文件名、播放时长、随机。
- 分类、排序、方向、布局按服务器会话（含用户）和媒体库保存；筛选留在当前页面会话。
- 标签分组中的标题排序和随机排序作用于分组名称；其它排序字段在分组上没有元数据，使用名称稳定排列。进入分组后使用完整媒体排序。

## 数据和导航

先按 200 项分页读取当前媒体库的完整元数据，再在本地分组、筛选和排序，界面分批显示 60 项。这样文件名、分辨率和随机排序覆盖整个范围，不会在追加分页时变换顺序。缺失排序字段始终放在末尾；同值按名称和 ID 稳定排列。大型媒体库首次加载时间和内存用量会随条目数增长；加载期间显示元数据读取进度。首次加载仍按页发布进度，但中间页更新会节流（约 400 ms），避免每页都在主线程重新筛选和排序整份累计目录。

列表、文件夹和合集读取显式请求 `CommunityRating`（[Emby ItemFields](https://dev.emby.media/reference/pluginapi/MediaBrowser.Model.Querying.ItemFields.html)），确保首次展示就包含服务器评分，无需进入详情页补齐。年份和时长从标准 DTO 读取。旧版目录快照仍可先显示，但会自动刷新一次以补齐评分；刷新失败保留旧快照，成功后继续沿用 30 分钟缓存策略。目录因该策略过期而自动重载时同样绕过 HTTP 缓存（`Cache-Control: no-cache`），避免把仍然有效的旧 HTTP 响应重新写回并延长目录有效期。无法取得的文件路径、视频流或尺寸不伪造数据。

合集按当前用户可见的 BoxSet 读取成员，并与当前媒体库 ID 集合取交集，避免混入其它库的内容。成员按服务器会话和合集缓存在内存中（沿用 30 分钟策略），同一服务器的其它媒体库可直接复用；缺失成员最多 4 个并发读取。手动刷新时失效。刷新失败保留上一份完整合集，不会先把列表清空。

文件夹按 `recursive=false` 查询当前层，维护可返回的目录栈。当前层成员以最新目录条目补全，评分等元数据不会停留在进入文件夹时的旧值；目录查询只决定成员和顺序。筛选时保留通往匹配媒体的目录。照片复用 Android shared 的图片查看器，支持翻页和缩放。页面退出与目录返回分别处理。视频目录在服务端排除 `Photo`，文件夹和 `PhotoAlbum` 保持可导航，客户端照片过滤继续作为兼容兜底。

播放停止上报成功后读取一次服务器 UserData，使已看阈值由服务器决定；媒体库不会把已看完的视频继续留在继续播放，也不会在下次全量刷新前显示旧标记。

随机播放与随机排序独立：当前筛选范围内可播放媒体组成打乱的队列，剧集展开为当前库内对应集数；播放结束继续下一项，也支持播放器上一项/下一项。照片与文件夹不加入播放队列。队列和当前位置随导航状态保存。

## 验证

```powershell
.\gradlew.bat :phone:testDebugUnitTest :data:testAndroidHostTest -PandroidAbis=arm64-v8a --console=plain
```

媒体库测试覆盖缺失字段位置、Windows/Unix 文件名、视频分辨率、日期时区、稳定随机顺序、剧集队列范围、媒体类型过滤、同值排序、目录筛选、合集筛选、合集成员缓存复用与失效、照片排除参数，以及刷新请求的 HTTP 缓存绕过。

编译和单元测试与设备安装、界面验收、真实服务器验收分开。本次不包含 TV 或 iOS 的开发和验证。
